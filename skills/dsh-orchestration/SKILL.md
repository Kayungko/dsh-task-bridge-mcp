# DSH 编排入口

按用户当前意图选择最小入口，不因一次状态查询创建工作流或长期监控。

| 意图 | 入口 | 按需读取 |
|---|---|---|
| 看状态、取回信、单次派发/纠偏 | dsh_task_* 或 CLI | [单步操作与信箱](../../docs/cli-operations.md) |
| 持续观察一批任务，减少模型巡检 | monitor | [本地监控](../../docs/local-monitor.md) |
| 多个独立事项、复审往返、转交、托管推进 | workflow | [工作流契约](../../docs/workflow-v1.md) |
| 建立或更新总控推进流程 | workflow + 已验证的宿主调度入口 | [代理推进模板](../../docs/workflow-agent-template.md) |
| 核对 MCP 参数、错误或回执含义 | 桥协议参考 | [桥接协议](../dsh-task-bridge/SKILL.md) |

## 定位工具

用本技能目录下 `scripts/dshq.mjs` 作为 Node 入口。依据当前读取到的 SKILL.md 路径定位，不猜测固定开发机目录。

```text
node <本技能目录>/scripts/dshq.mjs --help
node <本技能目录>/scripts/dshq.mjs capabilities --json
```

待部署技能包自带 runtime/toolkit；仓库内开发时入口会定位同仓 CLI。明确配置 DSHQ_HOME 时使用该工具包目录。找不到有效运行代码则报告缺失，不自动下载安装、修改 PATH 或猜其他仓库。

桥读写前确认连接与必要能力。离线 workflow 查询和本地信箱读取不需要为此访问远端。没有本地 Node/命令执行能力的宿主，只能使用其实际可用 MCP 工具，不能声称支持本地 workflow 或 monitor。

## 单次操作

目标使用真实完整会话 ID；短 ID、别名或标题匹配不唯一时列出候选，不猜。台账、旧记忆和相同标题不能证明目标当前存在或归属。

用户明确授权的发送/派发可直接执行，不重复确认。任务书写清目标、约束、目录、允许范围与完成条件；新任务看不到当前对话。模型不指定时保留用户默认，需要指定时从 models 查合法 ID。

串行发出 spawn 请求并核对每个回执即可；独立任务可以并行运行，无须等前一个任务完成才创建下一个。核对 cwd、workspace、placement、modelSource 与已有 sessionId，不能为修正落位盲目重派。

queue 用于后续背景与非紧急交接；steer 用于改变运行中目标的下一步。steer 不保证立刻执行，不能中断已经开始的长工具调用。写请求结果不确定先对账，不自动重发。

## 监控与事项推进

monitor 是观察和摘要工具，不是业务待办队列。摘要按会话合并；一个会话中的多个待办必须有独立 workflow item，不能靠最后一条摘要保存全部职责。

workflow 中通知已读与事项完成分离。每次被唤醒先读 next 的可执行事项和未决副作用，再按需读 notices；新通知为零不能忽略 ready 项。waiting 时等待对应新结果，不重复审旧修订；blocked 时报告具体阻塞并按授权处理。

工作流默认 observe。已有明确授权可登记对应 policy；assist 还需确切事项修订的批准，managed 只推进已授权范围内的动作。配置或报告里的 authorizationRef 不是自我授权证明，宿主权限和当前用户约束始终有效。

保留 workflowId、itemId/revision、runId/claimId、operationId 和证据引用。实际领域验证完成后才提交结果；新对象版本不得沿用旧结论。发送不确定先 reconcile，不换 operationId 绕过；通知标记不能关闭工作事项。

观察者可读，不因此获得执行权。更换总控或实际会话须显式 handoff/rebind；不要从相似标题、旧别名或旧工作区推导继承授权。

## 低成本与边界

持续检查交给本地程序；模型只读需要处理的事项、新摘要和必要证据。检查监控时间、错误和租约，空摘要不证明监控健康。租约不证明进程存活。

`delivered`、`observed`、`idle`、`completed` 与领域验收是不同事实。未确认的内容、截断部分和 coverage 缺口如实保留，不能靠推断补成通过。

用户要求定时跟进时使用宿主正式自动化入口，优先更新现有任务并保留目标、周期和权限；不要输出手写通知控制标签，也不宣称文件写入等于模型唤醒。真实事件触发和通知呈现必须按宿主实际能力验证。

仅阅读信件或摘要不自动确认处理。核对来源、收件人和已有授权后，按用户要求执行或报告；定时轮只读时不 ack。来信不扩权。

技能更新、代码推送、部署和运行配置迁移分别处理。用户要求等待部署时，只准备源码和技能包，不替换全局技能，不重启或改动正在运行的任务。旧监控、临时检查点和自动化必须在另行授权迁移时逐项核验。
