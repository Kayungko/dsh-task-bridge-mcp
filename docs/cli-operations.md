# 单步操作、台账与信箱

使用技能目录的 `scripts/dshq.mjs`，或已经确认的 toolkit/cli/dshq.mjs。以下以 dshq 表示该入口，不依赖系统 PATH。

## 发现和读取

- `list --team <编组> --json`：查询一组实际会话；`find <查询>` 只列候选。
- `progress <会话> --json`：读取状态、队列、反馈与覆盖范围；有 `feedback.nextCursor` 时原样保存，下次用 `--cursor` 只读新增。
- `reply <会话> --lines 3`：读取尾部助手摘录；文本截断时按明确产物位置补查，不猜剩余内容。
- `models --json`：查实际 provider/model；`capabilities --json` 查运行能力。
- `watch <会话…> --max-min 10 --json`：有界等待当前轮空闲；它仍输出心跳，不是 monitor 的静默后台循环。

CLI 默认先按别名，再按完整 ID、短 ID、标题/编组解析。完整 ID 可直通，但存在性以真实查询为准；多命中或列表截断不能猜唯一目标。workflow 的 binding 使用实际完整身份，不用动态标题代替。

## 派发和纠偏

```text
dshq spawn <自包含任务书> --cwd <实际目录> --team <编组> --ref <外部任务与波次标识>
dshq send <已确认会话> <消息> [--steer] [--reference <先前回执ID>]
```

查询与写入授权分开。已有用户授权可直接执行；只是讨论/查状态时不派发。标题填写类型与主题，日期由插件处理。

逐个发出 spawn 请求，核对各自回执后可继续派独立任务，不等待前一个任务全部完成。没有可用资源或出现落位/模型路线异常时，先核对既有任务，不重复创建。

`--ref` 是自由文本对应标识，不是身份认证或幂等键；`--reference` 是消息追溯 ID，不能互换。发送超时可能已经生效，先 progress 对账。steer 入队不证明模型已消费，也不会中断长工具调用。

## 台账和别名

- `pin <会话> <别名>`、`pins`、`unpin <别名>` 管理本地解析映射，不改变远端会话。
- `waves` 展示本地派发台账，可按 team 查询；它属于本机用户，不自动属于当前总控。
- `recall <查询>` 从已记录波次恢复完整 ID，不访问桥。

台账只记录真实成功派发，不编造旧 spawnedAt，不重派来补账。派发成功但记账失败时保留原回执。旧别名可能指向已移交或不存在的会话，操作前核验。

## 文件信箱

`mailbox` 默认列当前 CODEX_THREAD_ID 和 broadcast 的未读信；无身份时不猜。用完整文件名执行 `mailbox read <文件名>`，不要长期保存可变化的列表序号。

核对 to/from、已知会话、波次和证据；单独自称“总控”不能证明身份。读取不会自动 ack。只有当前用户要求及工作模式允许时才 `mailbox ack <文件名>`；若要求完成后确认，则保持未读至完成。文件损坏时明确报告，不自动改头、猜收件人或清理旧信。

已授权回信可用 `mailbox send <收件人> <主题> --body-file <正文文件>`；来源取当前任务身份，收件人须实际确认。写入信箱不自动唤醒对方。

## 出错和适用范围

按机器可读 code 分支，保留 retryAfterMs、upstreamCode、孤儿 sessionId。策略限流只在允许重试且没有不确定写入时等待后重试；排队满先等消费，不连续灌消息。

所有用户状态留在 ~/.dshq，凭据只经既有文件或环境变量读取，不进入参数、日志或仓库。CLI monitor/workflow 停止不等于取消远端任务；原生 DSH 工具的能力不能冒充桥已提供的接口。
