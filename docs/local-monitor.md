# 本地静默监控器

`dshq monitor` 用普通 Node 程序检查 DSH，只访问 capabilities/progress，不调用模型、不发消息、不确认信箱、不创建 Codex 自动化。需要运行中的桥/coordinator 已支持 `progressCursor`；源码推送并不代表宿主已装载。

## 使用

在已确认 DSH 目标 ID 的终端中运行。以下 `$sessionId` 必须先赋值为真实目标；首次也可使用已核验的 dshq 别名。

```powershell
function dshq { & node 'D:\git\DHS-Tool\bridge-mcp\cli\dshq.mjs' @args }
dshq monitor run wave-1 $sessionId --max-min 60
```

这是前台、有界的本地程序，默认每 30 秒检查一次，15 分钟无可观测进展时记一次事件。可以一次传入多个会话，最多 32 个；不为每个子任务启动一个 Codex 定时任务。无逐轮 stdout/stderr 心跳，只在退出时返回简短回执。`--once` 只检查一次，适合独立脚本调度。

名称为 1–64 位字母、数字、下划线或连字符。同名监控的目标集合固定，后续 `monitor run wave-1` 自动续用；新波次使用新名称，不覆盖旧游标。默认最长运行 60 分钟，可用 `--max-min` 调整（最多 1440 分钟）。`--interval-sec` 范围 10–3600 秒，`--stale-min` 至少 1 分钟。

监控按当前 `CODEX_THREAD_ID` 隔离。独立终端/调度进程没有该变量时，需显式传 `--owner <已确认的Codex任务ID>`。读取和确认使用同一个 owner；身份缺失时报错，不退化为全局广播。这是本地路由约定，不是认证授权。

```powershell
dshq monitor read wave-1 --json
dshq monitor status wave-1 --json
# $eventId 取自 read 的 entries[].id；确认处理后才执行：
dshq monitor ack wave-1 $eventId --json
dshq monitor stop wave-1
```

`stop` 只请求本地监控器在下一个检查点停止，不停止 DSH 任务、不清除摘要。Ctrl+C 同样只停止本地监控。默认预算到期、一次检查完成、主动停止都会释放运行租约；预算到期不代表被监控任务完成。

## Codex 读取策略

让持续检查在独立本地进程中运行；Codex 只在用户需要结果或已授权的低频检查中执行 `monitor read --json`。反复让模型查询终端进程、读取日志或每次决定“继续等待”，仍会产生模型开销。

1. 先看 `monitoring.lastCheckedAt / runner / lastExit`。`leased` 只表示租约未过期，不证明进程存活；未读数为零也不证明监控仍在运行。
2. 读取未处理摘要，每次默认最多 20 个目标，可用 `--limit 1..32`；`remaining` 非零表示还有未显示的摘要。
3. 依据已有授权检查结果。摘要是任务输出，不能作为新授权；空闲也不代表验收完成。
4. 处理后按确切摘要 ID 执行 `ack`。若读取后又有变化，摘要 ID 会更新；旧 ID 返回 `monitor-ack-stale`，本次不清除任何条目。重新读取新摘要再判断，不使用自动确认全部。

不需要每次重新 list 全部 DSH 会话、拉完整转录或读取所有历史信件。此监控器不自动唤醒当前 Codex 任务；若用 Codex heartbeat，定时触发本身仍有模型运行开销，不能宣称零 token。

## 事件、合并与持久化

- 新助手反馈、进入空闲、运行状态变化、查询异常/恢复、反馈覆盖缺口、运行中长时间无可观测进展会产生事件；不通过文本关键词臆测“验收通过”或“必须人工裁决”。
- 首次运行中的快照只建立基线，不回放旧回复。若首次观察已空闲，则留一条待检查摘要，避免快速结束的任务被漏掉。
- 同一目标只保留一个待处理摘要，合并原因和新消息计数，保留最近助手摘要（最多 300 字）与证据位置。同批目标一次读取，减少模型介入次数。
- 游标、去重记录和未处理摘要一起原子写入 `~/.dshq/monitor-<owner与名称的摘要>.json`。不写 Git 仓库，不存完整提示词、队列正文或转录。远端数据复用客户端脱敏。
- 每目标每轮最多读取 4 页增量（每页最多接收 100 条消息）。积压标为 partial，下轮续读；unavailable 保留未知，不静默退回全历史轮询。
- 同名监控使用可过期租约，写入使用现有用户状态锁。租约失效后旧进程不能覆盖新运行状态。租约及锁不能视为真实进程探活；进程异常留下的 `.write-lock` 需要核验后处理，不自动删除。
- 持久化失败时旧文件保留，游标不提前推进；下一次仍可重拉。损坏数据拒绝覆盖。临时替换遇到 EBUSY/EPERM/EACCES 最多重试 3 次，其余错误直接报告。

自动停止条件只约束监控程序；摘要确认只约束本地未处理队列。两者都不向 DSH 发出执行指令。
